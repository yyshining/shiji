# 拾迹：产品设计说明

## 定位与范围

面向希望轻量记录旅行的个人与同行者，连接旅行准备、当日安排、即时记录与事后回看。本项目是个人产品实践，需求来自场景分析和持续的原型反馈；尚未开展可报告的正式用户访谈、可用性样本研究或商业验证。

希望验证的假设是：把分散内容绑定到旅程与日期，能够降低记录和回看时的切换成本。是否成立仍需用户测试。

## 主要使用路径

1. 新建旅程，确认日期和同行人，补充出发清单。
2. 在日程中安排交通、住宿与体验；随时记录一段文字或几张照片。
3. 心情日记承载整段旅程的感受，账本处理共同支出的归属。
4. 结束旅程后进入回忆；继续按天查看、补记和编辑，不复制出另一套数据。

## 迭代中解决的问题

| 发现的问题 | 取舍 | 落地结果 |
| --- | --- | --- |
| 在途与回忆使用不同分类，日记和清单在归档后难以找到 | 保留首页阶段入口，统一旅程内部三栏 | 概览 / 日程 / 账本共同访问同一旅程 |
| 日程总览重复所有日期内容，信息冗余 | 总览先概括，再看明细 | 用每日内容分布呈现节奏，日期页编辑具体安排 |
| 清单拖动只出现插入线，移动感不明确 | 强化被拖动对象的视觉反馈 | 整行跟随移动，相邻行让位 |
| 日记输入区域不明显，保存按钮打断书写 | 采用可识别的纸张编辑区与自动保存 | 心情印记、横线、字体选择 |
| 小程序直接使用系统选择器与默认按钮，偏离原型 | 公共导航、选择器和间距统一适配 | 迁移工作已启动，仍未完成全量视觉验收 |

## AI 如何参与流程

优先选择边界明确的「文字行程结构化」，而不是开放式万能聊天：

```mermaid
flowchart LR
  A[用户主动粘贴文字] --> B[云函数调用模型]
  B --> C[字段与类型校验]
  C --> D[草稿列表]
  D --> E[人工核对和修改]
  E --> F[保存到旅程]
```

模型提取日期、时间、地点与安排类型；无可靠依据的字段应留待用户补齐。开发环境中已观察到一条合成行程拆成交通与住宿两条，并正确带入编辑页。**这只是一次联调结果，不是准确率评测。** OCR 尚未接入。

AI 辅助开发用于实现、排错和生成测试；作者负责产品目标、交互取舍与评审。现阶段展示的能力是拆解问题和推进验证，而非声称已验证某个业务收益。

## 后续验证计划（未执行）

- 任务可用性：首次创建旅程、补记住宿、归档后找回日记的完成情况与卡点。
- AI 质量：构建含缺失日期、跨夜住宿、多地点和模糊描述的标注集，统计字段准确性与人工修改情况。
- 可靠性：弱网保存、跨设备备份恢复、并发冲突、不同微信账号的访问隔离。
- 不提前设定或编造完成率、节省时长、留存率等结果。
