## 打开项目

导入本仓库根目录，根配置已设置 miniprogramRoot 与 cloudfunctionRoot。公开仓库需要配置自己的 AppID 与云环境。

## 必需配置

1. 用户在微信云开发控制台选择或开通环境。开通涉及平台条款及可能的费用，由用户确认。
2. 在该环境创建 `shiji_private` 集合，客户端读写权限设为禁止（只允许云函数通过服务端 SDK 访问）。此集合保存每个微信用户独立的备份和 AI 用量计数，不用于多人共享。
3. 云存储规则仅允许文件创建者读写；客户端每次上传产生新的文件，不覆盖他人的对象。部署后必须用两个测试账号核验隔离。
4. 将公开的环境 ID 填入 miniprogram/lib/config.js 的 cloudEnv。不在该文件放密钥。
5. 部署 shijiGateway 云函数（Node.js 18 或更新运行时），安装 package-lock.json 中锁定的依赖。执行超时应大于 20 秒的上游请求超时，建议 60 秒。
6. 云函数环境变量配置 `AI_BASE_URL`（兼容 Chat Completions 的 HTTPS API 根路径，通常包含 /v1）、`AI_MODEL`、`AI_API_KEY`。密钥只在云控制台配置，不提交仓库或聊天。模型输出需支持文本 JSON；当前不含图片 OCR。
7. 云函数调用源限制为本小程序，不开放 HTTP 匿名入口。所有操作使用 getWXContext 的 OPENID，忽略客户端自报身份。

## 数据与交互边界

- “我的 → 云端备份与同步”提供手动上传和取回。照片先上传云存储，云端备份使用 fileID；本地原图引用保留。
- 并发版本不匹配拒绝覆盖。取回前明确确认，保存一份本机副本，页面提供恢复入口。当前不是自动合并或多人实时协作。
- 首次使用新账号不会自动上传已有本机资料，需要点击备份。云端操作失败不影响本地编辑。
- 天气经云函数请求固定的 Open-Meteo 和 Wikipedia 端点，不关闭小程序域名校验。当前限定示例地点和最多 31 天范围；服务端缓存 30 分钟，仅全部成功才缓存。
- AI 入口向用户说明发送范围；只发送主动粘贴的文字，不自动发送整本日记、账本或照片。输出校验后展示草稿，必须进入编辑页确认保存。每用户每天最多 20 次模型整理调用。
- 单次备份上限 800 KB（照片二进制在云存储，不算入文档），超过会拒绝并保留本地。

## 上线前实际验收

- 两台设备同一微信账号上传/取回；不同账号不可读取对方备份或文件。
- 同一云版本并发写入只能一个成功，冲突方本地不丢失；取回前的副本可恢复。
- 相册照片跨设备可显示；中断上传可重试。
- 真实天气、百科请求成功与失败态；AI 真实请求、无日期资料、畸形返回、用量上限、人工修改后保存。
- 当前本地模型/适配器测试无法证明部署权限、真实网络、计费或设备显示已通过。
